# PipWise (Expo + TypeScript)

Educational forex app. Not financial advice. No trade signals, no live trading.

## Folder guide
- `src/app/`        screens and routes (Expo Router). `(tabs)/` = News, Learn, Practice, Profile
- `src/components/` shared UI (`index.ts` re-exports everything)
- `src/lib/`        Supabase client, theme, session and plan state (`index.ts` re-exports)
- `android/`        native Android project (generated by `expo prebuild`), contains `gradlew`
- `supabase/`       database SQL
- `package.json`    JavaScript dependencies and the pinned pnpm version. `"main": "expo-router/entry"` is the entry point.
- `pnpm-lock.yaml`  Reproducible JavaScript dependency versions; commit changes to this file.
- `pnpm-workspace.yaml`  Keeps a hoisted dependency layout for the existing Expo/native build setup.

## Two kinds of dependencies
- **JavaScript (pnpm):** `pnpm exec expo install <package> --pnpm`. Go in `package.json`.
- **Android native (Gradle):** `./gradlew` reads `android/build.gradle` and `android/app/build.gradle`,
  downloads Android libraries, and builds the app. Expo and React Native modules add their own
  Android parts automatically when you build, so you rarely edit these files by hand.

## Run
1. Use the pnpm version pinned in `package.json`, then run `pnpm install --frozen-lockfile`.
2. Copy `.env.example` to `.env` and fill it in. Run `001_profiles.sql` in Supabase.
3. Quick dev: `pnpm start` (Expo Go; RevenueCat will not work there).
4. Gradle build (needs JDK 17 and Android SDK installed, `ANDROID_HOME` set):
   - `pnpm android:build`  runs `cd android && ./gradlew assembleDebug`
     (APK: `android/app/build/outputs/apk/debug/app-debug.apk`)
   - `pnpm android:run`    builds and installs on a connected phone or emulator
   - `pnpm android:clean`  clears the Gradle build
5. After adding a package with native code, or changing `app.json` (name, scheme, plugins), run
   `pnpm exec expo prebuild --platform android --clean` to regenerate `android/`.

Run `pnpm lint` and `pnpm typecheck` to check changes. Use pnpm for dependency installation and keep `pnpm-lock.yaml` as the only JavaScript lockfile.

## Welcome and returning users

The launch animation uses the app's market artwork and respects the device's reduced-motion setting. New users choose English or Amharic, then answer three questions about experience, markets, and goals. Language and answers are saved together in AsyncStorage before onboarding is marked complete. Failed saves stay on the current screen for retry.

Returning users skip setup only when the completion flag and all three valid answers are saved. Signed-in and demo users then go to Trade; signed-out users go to authentication. Profile → **Onboarding questions** opens Question 1 directly. Profile → **Review onboarding** replays the full welcome and language flow. Both preserve the virtual wallet and lessons. Profile also lets users change language directly.

The native splash configuration uses `expo-splash-screen` and requires a new native build after regenerating the project from `app.json`. Check the final native splash transition in a release build; Expo Go does not reproduce all splash settings. The animated welcome itself uses React Native Animated and SVG, with no remote animation assets.

Run `node --test tests/*.test.cjs` to verify preference persistence, startup routing, and simulator behavior.

On Windows use `gradlew.bat` instead of `./gradlew`.
