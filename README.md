# PipWise (Expo + TypeScript)

Educational markets app with provider charts and a separate virtual trading simulator. No brokerage execution.

## Folder guide
- `src/app/`        screens and routes (Expo Router). `(tabs)/` = Trade, Learn, Analyse, Progress, Profile; News is a hidden supporting route.
- `src/components/` shared UI (`index.ts` re-exports everything)
- `src/lib/`        Neon authentication, application API clients, theme, session and plan state (`index.ts` re-exports)
- `android/`        native Android project (generated by `expo prebuild`), contains `gradlew`
- `neon/`          current database migrations; `supabase/` retains legacy migration files
- `package.json`    JavaScript dependencies and the pinned pnpm version. `"main": "expo-router/entry"` is the entry point.
- `pnpm-lock.yaml`  Reproducible JavaScript dependency versions; commit changes to this file.
- `pnpm-workspace.yaml`  Keeps a hoisted dependency layout for the existing Expo/native build setup.

## Two kinds of dependencies
- **JavaScript (pnpm):** `pnpm exec expo install <package> --pnpm`. Go in `package.json`.
- **Android native (Gradle):** `./gradlew` reads `android/build.gradle` and `android/app/build.gradle`,
  downloads Android libraries, and builds the app. Expo and React Native modules add their own
  Android parts automatically when you build, so you rarely edit these files by hand.

## Run
1. Use the pnpm version pinned in `package.json`, then run `pnpm install --frozen-lockfile`.
2. Copy `.env.example` to `.env` and fill the public Neon Auth URL and application backend origin for the intended branch. Follow [the least-privilege setup and rollback guide](docs/DATA_LAYER_LEAST_PRIVILEGE.md) before deploying these changes. Security SQL is manual in the Neon SQL Editor; it is never run by startup or builds. Runtime uses `APP_RUNTIME_DATABASE_URL`, local migrations use direct `MIGRATOR_DATABASE_URL`, and GitHub retention uses `RETENTION_JOB_DATABASE_URL`; owner credentials have no fallback. Existing table names, owners and rows are preserved. A Neon Data API is not required. Keep the complete `.env` private.
3. Quick dev: `pnpm start` on port **8081** (Expo Go; RevenueCat will not work there). Keep one Expo server running; open web from that server with `w` instead of starting another one.
4. Gradle build (needs JDK 17 and Android SDK installed, `ANDROID_HOME` set):
   - `pnpm android:build`  runs `cd android && ./gradlew assembleDebug`
     (APK: `android/app/build/outputs/apk/debug/app-debug.apk`)
   - `pnpm android:run`    builds and installs on a connected phone or emulator
   - `pnpm android:clean`  clears the Gradle build
5. After adding a package with native code, or changing `app.json` (name, scheme, plugins), run
   `pnpm exec expo prebuild --platform android --clean` to regenerate `android/`.

Run `pnpm lint` and `pnpm typecheck` to check changes. Use pnpm for dependency installation and keep `pnpm-lock.yaml` as the only JavaScript lockfile.

If an installed Android app reports `Cannot find native module 'ExpoSecureStore'`, rebuild and reinstall the native app after adding SecureStore. With a USB-debugging Android device connected, run `pnpm exec expo run:android`; `pnpm start --clear` alone cannot add native modules to an older APK. SecureStore is already installed and configured for this SDK. Startup checks its native availability before importing it and shows a rebuild message when it is absent, preserving saved data and encrypted session storage.

## Welcome and returning users

The launch animation reveals the logo with lime orbits and market artwork, then opens language selection directly. It respects the device's reduced-motion setting. New users can choose English, Spanish, French, Portuguese, Arabic, Hindi, Chinese, Indonesian, Swahili, or Amharic, then answer three questions about experience, markets, and goals. Onboarding and core navigation are translated; lesson content remains in English. Arabic onboarding uses right-to-left text and controls without changing the app's global layout.

Language and progress are saved in AsyncStorage whenever users continue or go back. Interrupted onboarding resumes at the saved step. Failed saves keep the current screen available for retry; final completion is marked only after the complete preferences have been saved. In release builds, returning users skip setup only when the completion flag, all three valid answers, and the current onboarding version are saved. Older installs run the updated language-and-question flow once, preserving their wallet and learning progress. Finishing setup opens login/sign-up unless an actual account is already signed in; continuing in demo mode is an explicit choice there. On later release launches, signed-in and demo users go to Trade, signed-out users go to authentication, and valid deep links are retained. Profile → **Settings** → **Onboarding questions** opens Question 1 directly; the prominent **Replay onboarding** button starts with language selection. Settings also offers all ten languages directly.

The native icon yields to the in-app splash as soon as the root view is laid out. Fonts and animation callbacks have bounded fallbacks, and stalled storage/session reads show a retry screen after 10 seconds rather than leaving an endless splash. No unread workspace is treated as an empty profile.

Setup writes also have a bounded UI wait. A timed-out write stays in the physical serialization queue, expired retries are skipped, and late results do not commit stale preferences to memory. Continue becomes available again with a translated retry message. Clearing a setup entry query no longer remounts the wizard during a step change.

Development reloads replay language selection and the three questions by default, including on an already-completed local profile. This works with `pnpm start` on **8081**, without a special command or clearing app storage. An unfinished flow resumes at its saved step; a completed flow starts at language selection again with saved answers preselected. Finishing setup exits preview mode for that run and opens account access. `pnpm start:setup` is an optional alias that also clears Metro's cache. To test release-style returning navigation during development, start the single server with `EXPO_PUBLIC_PREVIEW_ONBOARDING=0 pnpm start`. Production builds always use saved completion and ignore the preview setting.

After the current onboarding version is complete, use **Replay onboarding** to view the new screens again without clearing app storage. If Metro reports `No apps connected`, reopen the app from the running server's QR code (or reconnect the emulator), then reload. Start the project with `pnpm start --clear` when checking a stale bundle. A `debugger-shell` `SIGSEGV` is a desktop DevTools process failure, separate from the app's JavaScript; GTK/VAAPI messages alone do not identify its exact cause. For the browser-based debugger fallback supported by the installed CLI, start `EXPO_DEBUG=1 pnpm start` and open `http://localhost:8081/open-debugger` in Chrome or Edge while the phone app is connected. Use the actual Metro port if it differs from 8081.

The native splash configuration uses `expo-splash-screen` and requires a new native build after regenerating the project from `app.json`. Check the final native splash transition in a release build; Expo Go does not reproduce all splash settings. The animated welcome itself uses React Native Animated and SVG, with no remote animation assets.

Run `node --test tests/*.test.cjs` to verify preference persistence, startup routing, and simulator behavior.

The chart gesture stage also requires a fresh APK. Follow the [chart gesture checks and build instructions](docs/CHART_GESTURE_STAGE_1.md) before accepting pinch, pan, inspection, and performance on a phone.

The bright Trade stage has its own [build-identity and phone checklist](docs/BRIGHT_TRADE_STAGE_1.md). Build with `pnpm beta:android`, then confirm **Trade UI: Bright 1** and the installed native version/build in **Profile → Settings**. Compare the completed EAS artifact's actual Android version code before any Play upload; system bars remain visible in this stage.

The current Android release implementation, build commands, public legal URLs, Google OAuth/signing details and remaining owner actions are in [GOOGLE_PLAY_RELEASE_AUDIT.md](docs/GOOGLE_PLAY_RELEASE_AUDIT.md). Paste-ready store content and the closed-test plan are in [GOOGLE_PLAY_RELEASE_CONTENT.md](docs/GOOGLE_PLAY_RELEASE_CONTENT.md). Activate the prepared feedback-retention workflow before relying on scheduled cleanup; see [RETENTION_SCHEDULER_SETUP.md](docs/RETENTION_SCHEDULER_SETUP.md).

All mobile build profiles now use the public-only EAS `production` environment; the hosted backend uses its separate `preview` environment. Keep server database/email secrets out of the mobile build environment. Every protected API call now includes a current session proof as well as its JWT. APK build 5 predates this change, so rebuild and reinstall after the manual database setup and matching backend deployment. This repository change does not update either deployment automatically.

Settings offers permanent account deletion after recent authentication, followed by clearing this installation's local data and returning to onboarding. Public `/privacy-policy` and `/delete-account` routes bypass onboarding/login startup guards, including when a saved wallet cannot load. The website also provides an email deletion-request fallback. Native Google deletion reauthentication preserves a safe return path across app restarts.

The current release target is **Android only**; Apple membership and Apple sign-in are not needed for it. See [BETA_TESTING.md](docs/BETA_TESTING.md) for Android APK/Play distribution, Neon email and social sign-in configuration, and private tester feedback. `pnpm beta:android` starts a standalone Android preview build. Use `pnpm beta:check --profile production --platform android` before the Android store build. The guide also retains optional TestFlight steps for a future iOS release. Release builds preserve normal returning-user navigation and run without Metro. Profile → Settings → **Send feedback** accepts signed-in reviews after applying the current Neon feedback migration; demo users can copy/share a report themselves.

The hosted browser beta is https://pipwise--beta.expo.app. Google sign-in uses the system browser on Android, a hosted `/native-auth.html` return page, and Neon's verifier exchange. Both provider flags default to off. Configure your own Google web OAuth credentials in Neon, deploy the return page, register its trusted origin, then enable Google in a test build. Keep Apple disabled for Android. A Google Cloud project stores the login configuration; a Play Console account separately publishes the app, so a friend's Play publishing access does not automatically supply Google login credentials. Follow the guide's email delivery, migration, and physical-device checks before sharing a release; local changes do not update the deployed website or existing builds.

## Reference-style workspace

Trade opens the **moving in-app demo market** with seven simulated assets, key levels, virtual orders and matching P/L. Provider charts remain an optional display mode; custom raw feeds still await permitted access. Signup includes a full name, country and optional contact phone, with email-code verification. **Profile → Chart coach** offers free on-device candle-file studies and a manual ChatGPT handoff: inspect/share a text prompt, open ChatGPT separately, and attach a photo yourself. ChatGPT's account limits apply. Automatic photo reviews stay disabled until owner-supplied model access is configured. See [account and chart-coach setup](docs/ACCOUNT_AND_CHART_COACH.md) and [market data boundaries](docs/MARKET_DATA.md).

The main tabs use a floating charcoal navigation bar and mint accents. Trade uses a bright practice workspace with seven moving simulated markets, an interactive line/candlestick chart, moving-average controls, and virtual order entry. USD/JPY collateral and P&L are converted into the dollar wallet. Open positions can be closed from **Portfolio**, accessible from Trade's information sheet or Profile.

Wallet saves capture their matching demo-price snapshot before entering the storage queue. Restored moving positions require saved prices; missing or corrupt prices show a retry state without overwriting the wallet or fabricating new P/L. Invalid saved trades are detected before portfolio calculations.

Learn contains 83 lessons across nine chapters, with a sequential lesson path, quizzes, saved bookmarks, and local completion progress. Analyse contains ten chart exercises: choose Up or Down, reveal five held-back simulated candles, and review the result. Exercise scores do not change wallet funds. Portfolio retains the equity curve, performance statistics, and filtered trading history.

Sign-up collects a required full name and saves it on the Neon account. Profile displays that account name and email, along with the existing learning preferences. Authenticated name edits save remotely and refresh the canonical session; demo names and illustrated avatars remain on-device, with local avatar ownership checked against the account. Profile also supports swipeable statistics, Open/Closed trades, settings, and invitation sharing. Pro uses real RevenueCat offering prices and store purchase/restore calls when configured; without offerings it shows free learning and practice options. Progress shows actual local lesson and closed-trade counts. AI screenshot reviews and production legal documents still require their respective services or published content. Invitations carry no membership rewards; the broker guide provides comparison questions.

On Windows use `gradlew.bat` instead of `./gradlew`.
